- (decision) Sources: final PRD (prd-todo-app + addendum) and final brief (brief-todo-app + addendum) are primary inputs.
- (decision) Constraint: docs/PRD.md and docs/bmad_exercise.md are the originals; UX must not deviate from them in any major way.
- (decision) Stakes: hobby / exercise project (learning BMad). Working mode: coaching path.
- (decision) Feel: calm and minimal; fast, slick, easy, clutter-free, intuitive; a helpful tool, never a hindering one.
- (decision) Form factor: web, used on both laptop and phone (laptop-first per PRD NFR-3, phone fully usable at 360px).
- (decision) Phone use mirrors laptop use (same journeys UJ-1..3, no phone-specific journey). Journeys reuse PRD UJ-1..3 verbatim with protagonist Peter.
- (decision) Visual direction: B 'Ledger' (cool neutral, compact rows, hairline dividers, right-aligned monospace age labels, age colour as thin left bar only; label text in main text colour) with the round filled check icon from C for completed tasks. Ref: .working/directions-1.html
- (decision) Colour modes: light + dark; follows system by default with an in-app toggle to override.
- (decision) Tick control: open tasks show an empty ring at row start; clicking fills it into the round check (from C) and completes the task. Same control unticks.
- (decision) Delete control: on laptop (hover-capable pointer) the delete x appears on row hover or keyboard focus; on phone/touch it is always visible at low emphasis. Delete stays instant, permanent, no confirmation (FR-13).
- (decision) Theme toggle: three-way effective behaviour — defaults to system; user choice is remembered per browser (local storage), no server involvement.
- (decision) FR-4 new-task visibility: a just-added task appears directly under the input for ~3s, then animates down into its sorted place; with prefers-reduced-motion the move is instant (no animation).
- (decision) Palette: Slate (variation 1 in .working/color-themes-1.html) as rendered, light + dark. Light: bg #F2F4F7, surface #FFFFFF, hover #F4F6F9, text #18202C, secondary #475263, muted #5B6676, divider #DEE3EA, accent/fill #4A5E7C, ring #7D8A9C, delete #5B6676. Dark: bg #0E131A, surface #151B24, hover #1B222D, text #E4E9EF, secondary #AAB4C2, muted #8E99A8, divider #242C37, accent/fill #98ACC8, ring #667385, delete #8E99A8. Age gradient: fresh <1h, overdue >=24h, t=(hours-1)/23 linear, OKLCH interpolation (L,C linear, hue 155->25). Light stops #249057 (<=1h) #428D42 #638718 #8F7506 #AE5F01 #C44231 #C43F3E (24h+); dark stops #55C483 #6EC06D #8FB74A #C19E00 #E28120 #EB6D5A #EA6A64. All pairs AA-verified in file comments.
- (assumption) User accepted Slate 'as it looks': light-mode olive/mustard mid-stops and coral-leaning dark red kept as rendered (not explicitly discussed).
- (decision) Typography: Inter webfont for UI text plus a monospace webfont for age labels (identical look across devices; accept small font download, must not delay input usability).
- (decision) Header: tiny quiet app wordmark on the left, sun/moon theme toggle on the right, above the input.
- (decision) Toasts: appear at the top, directly under the input, overlaying the top of the list; they never cover the input or take focus (FR-18).
- (decision) Wordmark text: 'Todo'.
- (decision) Mono font for age labels: JetBrains Mono (with Inter for UI text).
- (decision) Toast/held-task collision: toasts float as an overlay under the input; nothing in the list shifts.
- (override) Add-failure toast copy never echoes the task text: always 'Couldn't save new task.' Overrides PRD FR-16's 'toast shows the failed task's text' in the case where the user has already typed new text (failed text is then not recoverable from the toast). Text still returns to the input when the input is empty.
- (decision) Microcopy accepted: placeholder 'What needs doing?'; empty 'Nothing waiting. Type a task above and press Enter.'; action failed 'Couldn't update that task. It's back as it was.'; load failed 'Couldn't load your tasks.' + Retry; SR labels 'Mark "X" done' / 'Mark "X" not done' / 'Delete "X"' / 'added 5 hours ago' / 'completed 2 hours ago'; toggle 'Switch to dark theme' / 'Switch to light theme'. Loading = quiet skeleton rows, no text.
- (decision) Keyboard: plain Tab order (input -> each row's ring -> delete) with Space/Enter to activate and focus back to input (FR-2), PLUS shortcuts: Up/Down arrows move between rows, '/' jumps to the input from anywhere outside it.
- (decision) Motion: rows slide smoothly (~200ms) to their new position on tick, untick and when a held new task settles; instant under prefers-reduced-motion.
- (assumption) Keyboard details: Down arrow from the input moves focus to the first row; Esc from any row returns focus to the input.
- (event) Discovery closed: single-screen IA covers all PRD needs (FR-1..18); journeys UJ-1..3 all land on it on laptop and phone.
- (decision) Theme toggle is 2-state (light/dark) once chosen; no in-app way back to 'follow system' (clearing site data resets). Resolves OQ1.
- (decision) Rapid adds: each new add ends the previous task's hold immediately (it slides to its sorted place); only the newest task is held under the input. Resolves OQ2.
- (decision) Too-long add failure toast: 'Couldn't save new task. It's too long.' (explains why per FR-3, no echo of text). Resolves OQ3.
- (decision) Completed style stays Ledger: filled round check, muted text, no age bar, no strikethrough, 'done 2h' label. Complies with FR-11 (strikethrough was only an example). Resolves OQ5.
- (decision) Drop the '/' shortcut (WCAG 2.1.4). Return to input via Esc from any row or Up from the first row.
- (decision) Touch devices: no autofocus on load and no focus return to the input after tick/delete (avoids keyboard pop-up); laptop/keyboard keeps FR-2 exactly. Deviation from FR-2 literal wording on touch only.
- (decision) Header (wordmark + toggle) and input are sticky at the top; held new task and toasts stay visible regardless of scroll; focus return never jumps the page.
- (decision) Actions on an unconfirmed new task are allowed: tick/delete apply instantly in the UI and are sent once the add is confirmed. If the add fails, the task disappears with 'Couldn't save new task.' and no text is returned to the input.
- (decision) Focus safety net: when the focused element disappears (toast closes/auto-dismisses, row re-renders, Retry succeeds) focus goes to the input (keyboard/laptop). Toast timers pause while hovered or focused.
- (decision) SR success announcements via one polite live region: 'Added: X', 'Marked done: X', 'Marked not done: X', 'Deleted: X'. Resolves OQ4.
- (decision) Input has a visually hidden label 'New task' in addition to the placeholder.
- (decision) Unfocused input border uses the check-ring colour (3.18:1 light, 3.87:1 dark) to meet WCAG 1.4.11.
- (decision) Reflow target is 320px CSS width (WCAG 1.4.10), up from 360px.
- (decision) Tick/untick race: last user intent wins; requests applied in order; on failure roll back to the last server-confirmed state.
- (decision) Load-failure toast has no close x; it stays until the list loads (FR-17).
- (decision) Housekeeping: add toast-shadow token; age colour is computed from the formula (stops are reference values); add List behaviour row; add delete-on-hover contrast row; remove resolved open questions.
- (decision) Toasts: max 2 visible (oldest dropped); the sticky load-failure toast sits below any held new task, never over it.
- (decision) Adds during loading or after a load error are sent normally; after loading they merge into sorted order; after a load error the list stays hidden until Retry succeeds.
- (decision) Multiple failed adds: only the first failed text returns to an empty input; later failures show only the toast and their text is lost (accepted trade-off of the no-echo rule).
- (decision) Hover-reveal of delete only when primary pointer supports hover (media hover: hover); a hidden delete is not clickable until revealed.
- (decision) Transient error toasts sit below the held new task (same rule as load-failure toast); the held task is never covered. Supersedes earlier 'toast overlays held task'. Resolves OQ1.
- (decision) Type-to-focus (laptop/keyboard only): when no control has focus (body), typing a printable character without Ctrl/Cmd/Alt moves focus to the input and inserts the character. Clicking blank space does not steal focus, so text selection + Ctrl+C keep working. Note: possible WCAG 2.1.4 scrutiny; defended as active only when nothing is focused; flag for a11y check in build. Resolves OQ2.
- (decision) Held new task with keyboard focus when hold ends: it slides to its sorted place with focus on it, scrolled into view (below sticky zone). Resolves OQ3.
- (decision) After the last delete, SR hears 'Deleted: X.' followed by the empty-state text 'Nothing waiting. Type a task above and press Enter.' (same as initial empty state). Resolves OQ4.
- (decision) Toast timing stays ~5s auto-dismiss with pause on hover/focus (FR-18). Resolves OQ5.
- (decision) Tick ring stays a button with accessible name 'Mark "X" done' / 'Mark "X" not done' (explicit action wording accepted despite repetition). Resolves OQ9.
- (assumption) OQ6-8 (client clock ahead of server, refresh with add in flight, refetch after sleep) deferred to bmad-architecture; remain in EXPERIENCE.md Open Questions marked Owner: architecture.
- (decision) Error toasts (action-error, add-failure, load-failure) use variant C from .working/toast-variants-1.html: soft red tint background error-bg #FCECEB / dark #382A30, border error-border #F3C7C3 / #643B3E (decorative), plus 16px circle-exclamation icon in error-icon #BA2B2E / #F2716A before the message (non-colour cue). All text/actions pass AA. No red left edge (would read as overdue bar). Accepted deviation from PRD §6 'age colour the only strong colour': tint is soft, icon is small.
