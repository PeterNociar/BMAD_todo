- (event) Brief started from docs/PRD.md (prose PRD, single-user CRUD todo app, v1 excludes accounts/priority/deadlines/notifications)
- (decision) Stakes: practice project for learning BMad; no other source docs; right-size brief to light rigor, no market research
- (assumption) Platform (responsive web vs native) left open; user will clarify requirements as the BMad flow progresses
- (decision) Problem: small, low-importance tasks that come up during the day fall between tickets (too heavy) and paper (unreliable) and get forgotten; needs are fast capture and an at-a-glance list
- (decision) Working mode: coaching path, because user wants to learn the BMad Method end to end
- (decision) Platform: responsive web frontend (framework not yet chosen); backend Python FastAPI + SQLModel/SQLAlchemy + Alembic + PostgreSQL; detail kept in addendum for architecture
- (decision) Primary user: the author, as a standard user managing everyday personal tasks
- (decision) Success = working deployed app AND completing each BMad phase; learning goal covers all aspects of BMad
- (decision) Capture context: mostly at the laptop, so desktop-first with mobile secondary (PRD still requires mobile to work well)
- (decision) Capture bar: type and press Enter, nothing more; no required fields or dialogs
- (decision) Viewing pattern: glances at the list whenever there is a spare minute, not at scheduled review times
- (decision) List order: unchecked tasks first, newest added first; completed tasks shown below them
- (decision) New idea (beyond PRD): age indicator per task, green under 1h, gradient, red over 24h; purpose still to confirm
- (decision) Age indicator purpose: a nudge to act on tasks that have waited too long; this is the product's distinguishing idea
- (change) List order revised: red (over 24h) unchecked tasks first, then remaining unchecked newest first, then completed; replaces plain newest-first because it hid the oldest tasks
- (change) Cut 'heavier than the task itself' line from Problem draft; user did not claim it
- (decision) Overdue (red) tasks ordered oldest first, so the most neglected task is at the top
- (decision) Deferred to UX: a newly added task can be pushed out of view by many red tasks; user idea recorded in addendum
- (decision) Product success: user stops forgetting small tasks; capture from intent to saved in under 5 seconds
- (decision) Learning success: every BMad phase produced its document (brief, PRD, UX, architecture, stories) and the code was built from them
- (decision) Proxies for 'stop forgetting': tasks added on most workdays over two weeks; red tasks completed or deleted rather than piling up. Success Criteria draft accepted as written
- (change) Removed learning-exercise criteria from brief Success Criteria at user request; the learning goal (every BMad phase documented, code built from them) is still a project goal, just not a product criterion
- (decision) Scope: no manual priorities; automatic age-based ordering is in and must be stated explicitly so the PRD does not cut it
- (decision) Scope: no editing of task text in v1; fix a typo by deleting and re-adding
- (decision) Scope: delete is permanent in v1, no undo
- (decision) Completed tasks can be unchecked; an unchecked task returns to its place by its original added time
- (decision) Vision section dropped: practice app, no invented future
- (event) Finalized: memlog audit presented; bmad-review structure+prose applied to brief (7 fixes, persistence criterion kept as testable) and addendum (8 fixes, audit wording removed); status final
