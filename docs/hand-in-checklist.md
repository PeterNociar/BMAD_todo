## Known gaps

Each item is stated as its source states it.

- **Enter's feedback margin.** Enter's p95 is 94.5 ms against the 100 ms target, measured on an unthrottled machine, so a slower or throttled machine can fail the gate without a code change ([qa-performance.md](qa-performance.md)).
- **No throttled or phone measurement.** The performance check ran with no CPU or network throttling; throttling, phones and browsers other than Chrome were not measured ([qa-performance.md](qa-performance.md)).
- **No manual screen-reader pass.** Axe is not a full manual audit: screen-reader wording, announcement timing and zoom to 400% were not tested by hand ([qa-accessibility.md](qa-accessibility.md)).
- **No base-image CVE scan.** The base images were not scanned, because no image scanner is installed ([qa-security.md](qa-security.md)).
- **Open items in [deferred-work.md](../_bmad-output/initiative-todo-app/deferred-work.md).** Among them: the accepted security follow-ups (a `Host` allowlist, S-3; pinning or SRI for the CDN Swagger UI, S-4; the CVE scan), the `.dockerignore` test that checks wording rather than the real build context, and the unexplained JS heap figures in the performance report. The compose profiles and the nginx re-IP are covered only by the manual `scripts/check-infra.sh`, which no CI runs.

## Clean-checkout check

Run on 2026-10-02 for story 3.9, on the real port `8081`. It validated the app at `7ae9b39`, the clone did not include the 3.9 docs, by following the AD-16 commands, which 3.9 does not change. Per the user's decision, the running app profile was stopped first (`COMPOSE_PROFILES=app docker compose stop`; its data stayed in `db-data`), and the test stack was left alone.

```sh
git clone https://github.com/PeterNociar/BMAD_todo.git clean && cd clean    # origin/main = 7ae9b39
cp .env.example .env
docker compose -p todo-clean up -d --build --wait                          # 22.8 s, exit 0
```

`-p todo-clean` gives the clone its own project name, so its containers, network and `db-data` volume could not clash with the user's `todo` project. Output:

```text
2026-10-02T13:17:52+01:00
SERVICE    STATUS                    PORTS
backend    Up 16 seconds (healthy)   8000/tcp
db         Up 21 seconds (healthy)   5432/tcp
frontend   Up 9 seconds (healthy)    127.0.0.1:8081->8080/tcp
GET / -> 200
GET /api/tasks -> 200
GET /api/health -> 200
[]
```

The fresh database starts empty (`[]`). The build reused image layers cached on this machine, so 22.8 s is not a cold-build time. Afterwards, `docker compose -p todo-clean down -v` removed only the clone's containers, network and volume, and `COMPOSE_PROFILES=app docker compose up -d` brought the user's app profile back, healthy, with its tasks.
